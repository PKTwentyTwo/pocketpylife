
# Structure
This document explains how the files in the module are organised.
## genera
Three types of rule are currently supported: INT rules (```isotropic```, and they include OT rules as a subset), Generations rules (```generations```, both OT and INT are supported up to 26 states), and ruletable-specified custom rules (```custom```). Functions for handling the different types of rule are located in the folder ```genera```. These include:



 - [findgenera.py](genera/findgenera.py): Contains a function for identifying what type of rule a given rulestring is.
 - [generations.py](genera/generations.py): Contains functions for parsing Generations rulestrings.
 - [hensel.py](genera/hensel.py): Contains a class, RuleHandler, for parsing INT rulestrings using Hensel notation. It is used by some of the other rulestring parsers, as well as in the isotropic ```Lifetree``` code.
 - [ruleloader.py](genera/ruleloader.py): Contains functions for compiling a ruletable to Python code.
 - customrulesim.py: Not included in the repository, but instead automatically generated by ruleloader.py. It contains a function with a massive chain of if-statements. The speed of compilation and resulting size are not too bad - in the worst realistic case, it could take about 30 seconds and 1GB of disk space, but the speed of execution for custom rules is horrible.
 ## lifetree
 A ```Lifetree``` is the class used to simulate rules, and it works by creating a separate class ```Pattern```.
When ```pocketpylife.lifetree()``` is called, findgenera.py is used to determine which class of rules a given rulestring belongs to, then creates the corresponding type of ```Lifetree```.  There are four files that the class could be taken from:
 - [lifetree.py](lifetree.py): The original. It simulates INT rules.
 - [cylifetree.pyx](cylifetree.pyx): A Cython version of the above. It is slightly faster, but has to be compiled using ```pocketpylife.cython_compile()```, or by running the script [cycomp.sh](cycomp.sh), although the latter is mainly intended for development rather than deployment.
 - [tabletree.py](generationstree.py): A modified version that uses ruletables. It simulates rules using customrulesim.py, and has modified functions to allow working with multistate RLEs and apgcodes.
 - [generationstree.py](generationstree.py): A modified version that supports Generations rules. It mixes the INT algorithm from lifetree.py with additional code to support dying states and tabletree.py's multistate functions.
 ## gridops
 Pattern simulation is done using functions in the individual lifetree code files. However, functions used to manipulate the grid (e.g calculating hashes, applying transformations, determining apgcodes) are stored separately. There are two files which define grid operations:
 
 - [gridops.py](gridops.py): Contains standard grid operations, as well as the operations needed for multistate rules. Can be used by all three types of rule.
 - [cygridops.pyx](cygridops.pyx): Slightly faster, but specialised for INT rules, so only used by cylifetree.pyx.
